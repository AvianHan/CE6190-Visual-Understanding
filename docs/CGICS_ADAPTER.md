# CG-ICS adapter: components, protocol, and provenance

This document describes the wrapper contract and its differences from the pinned
upstream implementation. Experiment acceptance is recorded in the current report
and `results_summary/`; synthetic tests alone do not establish model performance.

## Input and output

`ics.adapters.cgics.create_adapter(settings)` builds the pinned official model
wrapper. `predict(inputs, seed=...)` accepts only an absolute query image path and
reference image/binary-mask paths. Query masks, category names, and evaluator
metadata are rejected. Output is a Boolean mask at the **original query size**, a
telemetry dictionary, and JSON-safe concept/search records. The restriction is an
API boundary, not an operating-system filesystem sandbox.

For example, a dog reference + dog mask and a different query image are processed
without the string `dog` being supplied by the evaluator. Any concept string is
generated by the MLLM from reference imagery.

## Pinned official source

- Repository: https://github.com/Kakarot1103/CG-ICS
- Commit: `8da845743f15c18ec490567fbd86dba58c8a388f`
- Main orchestration: `main.py`; model primitives: `model/sam3.py`,
  `model/mllm.py`, `model/tree_search.py`; the vendored SAM3 is used.
- The adapter checks HEAD and refuses modified tracked model/utils/SAM3 source.
- It does **not** import `main.py`, initialize swanlab, sample episodes, download
  models, or launch a remote service.

## Component combinations

| variant | Concept route | Visual route | Final prediction |
|---|---|---|---|
| `full` | upstream tree search, RF/QM scoring | stitch -> query masks -> boxes | query SAM3 with concept + boxes |
| `text_only` | identical upstream search | removed | query SAM3 with concept |
| `visual_only` | removed; no MLLM client/server needed | identical visual route | query SAM3 with boxes |
| `concat` | removed; no MLLM client/server needed | stitch | direct union of query-side instance masks |
| `no_search` | initial candidates + scoring/reranking, **zero expansion and zero restarts** | identical visual route | query SAM3 with concept + boxes |
| `single_concept_text` | one generated phrase, no scoring/search; 1-shot only | removed | query SAM3 with phrase |
| `single_concept_full` | one generated phrase, no scoring/search; 1-shot only | identical visual route | query SAM3 with phrase + boxes |

`variant="custom"` permits `concept_mode=search|candidates|single|none` and
`visual_mode=boxes|concat|none`. No-prompt and concept+direct-concat combinations
are rejected. A named variant cannot silently override its component definition.
Alpha/beta may be changed to isolate RF/QM scoring; `alpha=beta=0` retains the
upstream **random scoring** behavior and is not an unscored top-one selection.

`visual_only` and our unified `concat` are project-defined adaptations, not claims
that the anchors already reported these exact rows. INSID3 Table 9 has a related
SAM3 concatenation comparison; its unspecified prompt implementation is not
claimed to match ours. `no_search` keeps the visual branch present, whereas
CG-ICS Table 4 develops most search comparisons before adding that branch.

## Settings

Required: `upstream_dir`, `sam3_checkpoint` (or alias `checkpoint`). Defaults:

```json
{
  "variant": "full",
  "device": "cuda",
  "image_size": 512,
  "confidence_threshold": 0.5,
  "endpoint": "http://127.0.0.1:22002/v1",
  "mllm_model": "qwen3-vl-4b",
  "seg_type": "object",
  "BON": 5,
  "num_loops": 3,
  "num_expand_per_node": 5,
  "alpha": 1.0,
  "beta": 1.0,
  "expansion_threshold": 0.5,
  "max_restarts": 3,
  "early_stop_threshold": 0.8,
  "llm_seed_from_episode": false,
  "llm_seed": null,
  "llm_temperature": null,
  "request_timeout_s": 300
}
```

Use `api_key_env` for an environment-variable name when the local service requires
authentication; never put a secret in config. The default key is `EMPTY`, matching
the official local-vLLM example. A non-local endpoint requires
`allow_remote_endpoint=true`. Service deployment/GPU allocation is outside this
adapter. The requested Qwen revision may be recorded in `mllm_revision`; the
server launch record must verify it because an OpenAI-compatible model name does
not itself attest to checkpoint bytes.

Full source reference environment is Python 3.12, torch 2.9.0, torchvision 0.24.0,
CUDA 12.8; vLLM 0.11.2 is a **server** dependency. SAM3 client imports require its
vendored package dependencies plus NumPy, Pillow, SciPy, OpenCV and OpenAI SDK.
Do not mistake local CPU contract tests for validation of that GPU environment.

## Differences that must remain visible

1. Official code resizes each reference/query to **512 x 512**, followed by
   SAM3's own 1008 x 1008 preprocessing. This adapter preserves that default and
   records any changed `image_size`; it restores output by nearest interpolation,
   as the original evaluator does. The manifest evaluator uses original GT;
   some official loaders resize GT down and then up, so metric differences must
   not be attributed solely to the model.
2. The MLLM second view is a red-highlighted reference **crop** based on the
   largest connected-component box with extra context, not merely a full-image
   overlay. The exact official helpers and morphological component settings are
   reused.
3. The exact upstream search class is reused, including restarts, reranking even
   in 1-shot, the low-score literal `visual` fallback, and its BFS/max-depth loop
   condition. In particular the loop can stop when a deepest child is first
   reached while other frontier nodes remain; we do not silently replace this
   with a different complete breadth-first search.
4. A `full` final call is **not one head execution**: upstream first runs a text
   prompt and then adds boxes sequentially, running the head per box. Actual
   execution counters are used.
5. Import namespaces are isolated to avoid `utils` collisions. The official
   `sam3.sam3` imports are normalized to the pinned installed/vendored `sam3`.
   The exact tensor arithmetic of `normalize_bbox` is extracted to avoid loading
   an unrelated plotting module that runs K-means and resets NumPy's seed at
   import. Model initialization explicitly receives the device and prohibits
   implicit checkpoint downloads. These are packaging changes, not algorithm
   replacements.
6. Default upstream MLLM requests set neither temperature nor seed. A local
   PyTorch seed does **not** control the external vLLM sampler. Controlled runs
   can set `llm_seed_from_episode=true` and `llm_temperature`, and must report this
   departure from the unspecified original sampling. Server/kernel variations
   may still affect results; repeated runs are an empirical stability check.
7. Removed branches skip their unused image encodings. Full runs encode each
   reference, query and stitched image, as upstream does. There is no cache shared
   between episodes; all variants retain within-episode embedding reuse.

## What is measured

- `sam_calls`: calls entering `Sam3Segmenter.infer`.
- `sam_image_encoder_calls`: actual `model.backbone.forward_image` invocations.
- `sam_prompt_head_calls`: actual `model.forward_grounding` invocations.
- `mllm_requests`: attempted completions calls; SDK hidden retries are disabled.
- Prompt/completion tokens come from response usage, **not estimates**; absent
  usage makes totals unknown (`null`) and preserves any reported partial total.
- `candidate_score_evaluations` includes actual scoring and final reranking;
  the original search result's evaluation count excludes reranking, so both are
  separately named.
- Stage wall times synchronize the SAM device at boundaries. MLLM request time
  includes server queueing/network/generation, not isolated GPU compute time.
- External MLLM GPU memory is unknown here and recorded as `null`; it must be
  measured on the server allocation. It is not included in segmentation-process
  peak memory. Throughput with a shared server and isolated latency are distinct
  experiment settings.
- Model loading/checkpoint hashing occur at initialization. The outer runner
  measures them separately from per-episode inference.

## Interpretation

Text-only versus full measures the visual route's incremental contribution;
visual-only versus full measures the whole concept route's contribution.
No-search versus full (same visual settings) measures search/refinement including
restart behavior, with its additional requests. Concat versus full changes more
than one component and must be reported as a system comparison. None of these
comparisons establishes that SAM3/MLLM upstream supervision has been controlled
against original DINOv3-based INSID3.
