## Deployment

Apply the supplied incremental ZIP in the existing Mac Git clone. The installer
checks payload and old-file SHA256 values, backs up all replacements beside the
clone, preserves unlisted files and Git, and performs no commit or push.
Manually inspect, commit and push, then pull on Orion.

Suggested commit message:

```
fix(ics): load local DINOv3 weights and selectively recover missing experiments
```

On Orion, set the following environment explicitly:

```bash
export ICS_RUNTIME=/scratch/prj0000000262_1/hansy/ce6190-ics-runtime
export SLURM_CONF=/cm/shared/apps/slurm/var/etc/slurm/slurm.conf
export PATH=/cm/shared/apps/slurm/current/bin:$PATH
```

Check available storage first; 32 GiB is a startup guard, not an estimate of the
complete output footprint. Then use the supplied preparation command with
`--expected-missing 1392 --expected-preserved 92`, original parent fingerprint,
`configs/suite.initial.lvisfix.json` and `configs/cluster.orion.recovery.json`.
Successful preparation prints `PREPARED_NOT_STARTED`. Start it with:

```bash
"$ICS_RUNTIME/envs/insid3/bin/python" -I -B -u scripts/recover_ics.py start \
  --run-dir "$ICS_RUNTIME/runs/ics-recovery-20261113"
```

Use this recovery entry point for a stopped, nonterminal child manager. It
reuses the child's frozen source and state, reconciles accepted jobs before
submitting more, and does not reset task state. If the child is already terminal
with failures it returns 2 and does not retry those failures. Inspect evidence
before planning any further recovery. Do not use normal `queue_ics.py start`
to launch this child; it deliberately rejects recovery plans.

Read-only saved-state inspection:

```bash
"$ICS_RUNTIME/envs/insid3/bin/python" -I -B -u scripts/recover_ics.py status \
  --run-dir "$ICS_RUNTIME/runs/ics-recovery-20261113"
```

## Analysis and verification limits

The child collector contains recovered results only. Final coverage and analysis
must combine parent and child outputs by task/episode identity, retaining failed
attempt costs and distinct source provenance. Collector PASS alone proves no
model success. Repeated references for one query are not independent samples;
whole-system differences are not backbone effects; unified manifests do not
establish a complete reproduction of the authors' original evaluation protocols.

The available historical tests, new loader/scheduler/recovery tests, and installer
tests are documented in the bundle's VALIDATION.json. They include real archived
plan audit and synthetic scheduler/worker integration. Local tests do not load
real model tensors or run GPU inference. Orion GPU smoke and subsequent formal
results remain the acceptance evidence. No Orion jobs were launched by the
assistant while preparing this update.
