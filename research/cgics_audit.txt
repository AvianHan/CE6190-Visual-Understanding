Paper mechanism (arXiv section3; conference pp5-9):
Input only reference RGB+binary mask and query RGB, no ground-truth class name. Frozen Qwen3-VL-4B generates short concept candidates using original reference and red-highlighted target view. SAM3 evaluates RF=IoU(reference prediction, reference GT), QM=query presence probability; product ranks candidates. Expand surviving concepts, deduplicate, prune below0.5, stop at0.8, default N5/K3. Parallel visual path stitches reference/query horizontally, uses reference-mask-derived boxes, extracts predicted query-side masks and their boxes. Final SAM3 uses selected text+query boxes and returns semantic foreground mask. Multi-reference: independent concept search per reference, rescore final candidates across references; collect boxes from each stitched pair.

Critical fair-evaluation audit (source files in official repo, static findings):
1. COCO __getitem__ ignores index and samples class/query online with np.random. set_seed(seed+rank) means changing DDP world size changes episode draws. Use precomputed explicit episode JSONL IDs for comparative runs.
2. Most support loops exclude query but permit duplicate supports across nshot; decide paper-reproduction track vs unique-support common track and label both.
3. LVIS val classes filtered len(val_anno[class]) > self.shot, then divided by10; 1/5-shot can change class universe. Paper's920 needs checking against materialized preprocessed data.
4. main.py aggregates mean episode IoU within each class then macro mean across classes. It is not class sum-intersection/sum-union mIoU. Export both definitions if needed, never conflate.
5. GT resized to512 then upsampled for evaluation for most datasets; PASCAL reloads original GT and honors ignore255. Common evaluation should retain original GT and ignore masks, evaluate externally.
6. DDP DistributedSampler pads if length not divisible by rank count; identical manifest items may be counted twice. Use exact no-padding sharding.
7. main.py assumes batch size1 (.item(),squeeze and first support batch); expose/enforce bsz1.
8. FSS ignores num_test_samples option (len returns all images); explicit subset wrapper needed for smoke.
9. PASCAL split file path hardcoded data/splits/pascal despite --datapath. README says standard layout but check path before runtime.
10. main final per-class output block has lines indented after continue, unreachable. Fix only in isolated audited wrapper/patch, preserving upstream version.

Important implementation differences / research audit flags:
- MLLM highlighted view actually crop=True, largest-component bbox expanded1.3, alpha0.3; full original provided separately. Not merely unaltered full-image overlay.
- tree_search.py while frontier and max_depth_reached<num_loops exits as soon as first expansion reaches depthK; other depthK-1 frontier nodes may remain unexpanded. Paper describes round frontier expansion. Flag as potential semantic mismatch and validate with a tiny mock-tree test before changing.
- restarting is implemented only for all initial/restart candidates failing; paper wording can be read as restart in any failed round.
- client _call_api_once supplies model/messages/max_tokens128 but no seed/temperature, so Python seed alone does not control MLLM randomness.
- score<1e-6 falls back to prompt 'visual'. Log this and empty-mask cases.

Cost accounting (verified code):
- build_state image encodes2m+1 images per episode: m refs, one query,m stitched pairs, cached throughout episode.
- each candidate score invokes SAM3 head twice: reference+query. Image encoder is reused.
- final rerank executes2*m*m head calls for m final candidates acrossm references (including repeated query scoring and duplicate final strings); even1-shot reranks once.
- infer(prompt,mask) executes text head once then another head per valid box as boxes accumulate. Visual extraction executes one head per reference connected-component box. Thus high-level 'single joint SAM3 inference' is not a single low-level model forward.
- total_evaluations counts tree candidates only; excludes rerank, visual and final heads; no actual MLLM/API token counter currently.
- main wall-clock sample timer includes state/search/visual/final but excludes metric/visualization; no explicit CUDA synchronization. Only rank0 local average logged; MLLM GPU service separate. Need synchronized full pipeline latency, encoder/head/MLLM counts, tokens, search nodes/restarts, SAM peak memory and server memory separately, cold/warm modes, concurrency.

Recommended immediate common protocol actions (proposals, not runs): freeze explicit class/query/support IDs independently of model, rank and RNG; one input contract without label strings/query GT; external original-resolution metric; separate semantic object/part/instance tracks; cache responses only under explicit cache protocol; reproduce upstream first with exact settings, then common benchmark with documented adaptations; add component/budget controls to separate SAM3 backbone from MLLM/search gains.
