## 固定 episode 后再比较

`episodes.example.json` 是带虚构路径和哈希的格式示例，**不是 dataset、样本或结果**。正式 manifest 顶层字段为：

| 字段 | 内容 |
|---|---|
| schema_version | 当前为 1 |
| status | 正式运行前为 ready；示例为 example_only |
| protocol_id | 已锁定且有文字说明的协议版本 |
| episodes | 每条固定 query、reference 集合、track、split、fold、mask 语义及 ignore label |

每个 asset 都记录 image、mask 的相对路径及 SHA256。每次运行保留同一 manifest 和 fingerprint。正式校验会核对真实文件：

```bash
python3 ics_eval.py episodes.json --dataset-root /actual/dataset/root
```

validator 检查重复 episode、相同 reference/query 内容、重复 references、非法路径和文件哈希。路径校验不代替 dataset split provenance 审查；同一视频、同一病人、近重复照片仍须由 dataset adapter 按协议分组排除。

`inference_view(episode)` **只返回 query image 和 reference image/mask**。query mask、concept_id、query 类名均留在 evaluator 内。不要将完整 episode 传给模型，也不要使用 query annotation 生成 SAM prompts。该接口是程序级防误传，不是操作系统访问隔离。

semantic、personalized、part 独立汇总。对 instance mask 做 union、选择单一实例或组合 part，必须写在 protocol/mask_semantics 中并由 loader 实现。模型输入坐标和输出尺寸还须在 adapter 中检查。

## 三种聚合不能都简称 mIoU

`binary_counts` 接收**已映射为 0/1** 的展平 mask；ignore pixels 不参加统计。每个 episode 保存 TP/FP/FN/TN/ignored 原始整数。

| 输出字段 | 定义 |
|---|---|
| mean_episode_iou | 先算每个 episode 的 I/U，再平均所有 episodes |
| class_mean_episode_iou | 每个 class 内平均 episode IoU，再平均 classes |
| class_pooled_iou | 每个 class 的 ΣI/ΣU，返回按 class 的映射 |
| macro_class_pooled_iou | 平均上项各 class 的 pooled IoU |

例如 class A 有两个 episodes：I/U 为 1/1 和 0/9；class B 有一个 4/5。三个总体结果依次为 **0.60、0.65、0.45**。因此复现两个仓库前必须核对 evaluator，统一比较时同时报告明确的同一聚合方式。

空 union 的 IoU 为 undefined：此模块跳过并报告数量；若某 benchmark 规定空空为 1，应新增单独 protocol，不能静默改变。当前模块不计算 boundary metric、不做统计显著性推断。Fold 结果需按相应 benchmark 的官方规则另行合并；禁止直接把不同 dataset、method、track、run 或 reference manifest 的 rows 混起来。

reference robustness 的每个 reference seed 建议作为独立 run，使用相同 query 集，分别产出结果后统计 per-query spread；不要把更多 references 造成的重复 query 当作更多独立测试样本。bootstrap 必须以 query 或相应独立单位为 cluster，此模块尚未实现。

## 结果与成本合同

`examples/result.example.json` 全部数值是 null，表达**未知/未测量**，不是零。正式结果逐 episode 写 JSONL，并填入 commit、checkpoint/config/manifest 哈希和 prediction 文件哈希。失败保留记录及原因，不能从 denominator 静默删除。尚无 result JSON validator 或模型运行器。

成本需分别记录模型加载、reference preparation、query inference、postprocess、端到端时间。CG-ICS 另记 MLLM requests、tokens、等待/生成时间、tree-search nodes/candidates、SAM calls 和 cache hit/miss。SAM 的顶层调用（sam_calls）、image encoder 执行（sam_image_encoder_calls）和 prompt/head 执行（sam_prompt_head_calls）分别计数：复用 image embeddings 时，这三者不相等；一次顶层调用可能针对多个 boxes 运行 head。每个 adapter 必须注明实际插桩位置；计数来自真实执行处，不能用搜索深度或 box 数简单推算。

CUDA timing 需要前后 synchronize；并发 MLLM server 的成本需另外计量，单个 segmentation 进程的 `torch.cuda.max_memory_allocated()` 看不到 server 显存。多 GPU 按设备报告 peak 并注明测量范围，不将各设备不同时间的峰值求和称为瞬时总峰值。cold/warm cache 分开，不将 reference 缓存收益隐去。wall-time 子项可能重叠，不能盲目相加代替真实 end-to-end。
